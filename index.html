Abstract

Machine learning research agents repeatedly write, run, and revise programs. Each real execution can require training and evaluation before the agent receives useful feedback. MLE-World predicts that execution feedback directly from code and task context: terminal output, an exception class, and a validation metric.

The learned predictor is a fine-tuned Qwen3.5-4B model. Research agents use its reports to screen, compare, or improve candidate programs, while a confidence gate determines when to request real execution. Final submissions are verified through real execution. The experiments below separately examine prediction fidelity, search quality, and real-execution cost.

How MLE-World guides search

Predict a report for each candidate, select or combine programs, then decide when real execution is needed.

From a candidate program to an execution report

MLE-World is fine-tuned on agent trajectories pairing candidate programs with observed execution reports. It predicts one candidate's execution from its code and execution context.

MODEL INPUT

Code + execution context

  • Candidate program
  • Task and data description
  • Environment and runtime budget
→
PREDICTED REPORT

What the program would return

  • Terminal output
  • Exception class
  • Validation metric

The model also supplies an outcome-class confidence score. The fidelity evaluation below compares saved predictions with real execution.

Allocate real execution after candidate selection

The search policy returns a program. The confidence gate then decides whether its predicted report can supply feedback or whether the program needs to run.

  1. Check the selected candidate's report. Reuse an existing prediction; obtain a new one for newly synthesized code.
  2. Apply the outcome-specific threshold. Low or missing confidence requests real execution. Success and failure use separate thresholds; predicted timeouts are skipped.
  3. Verify improvements and final submissions. A new best predicted score triggers a real run. Final selection uses real validation scores.

Confidence is an outcome-class score, not calibrated accuracy. Candidate search and confidence-gated execution allocation are distinct parts of the method.
